# Tsets Partners — Company Website

A static, multipage website for the Tsets Partners law firm, built with Next.js
16.3.1 (App Router), React 19, TypeScript, CSS Modules, and next-intl. It includes
the homepage, firm information, 5 practice areas, 9 team profiles, interviews,
and contact information. Visitors can switch between Mongolian, English, and
Chinese in the browser. Language and appearance preferences are stored in
localStorage; languages do not have separate URLs.

The website has no database, API, or server-side contact form. The contact form
constructs a `mailto:` link and opens the visitor's email client; it does not send
a message itself. Fonts, images, and video are local assets. The hosting server
does not need to run Node.js, PHP, or `next start`.

## Development and structure

```bash
pnpm install
pnpm dev
```

Development URL: <http://localhost:3000>.

- `src/app` — pages and routing.
- `src/components/layout` — navigation, footer, language, appearance, and animations.
- `src/components/sections` — content components and the contact form.
- `src/lib/i18n/messages/{mn,en,zh}.json` — translations.
- `src/lib` — contact details, team members, and interviews.
- `public` — images and video; its contents are copied into the export.
- `src/app/fonts` — local fonts.

## Build and deployment package

```bash
pnpm lint
pnpm typecheck
pnpm build
```

`next.config.ts` sets `output: 'export'`, `trailingSlash: true`, and
`images.unoptimized: true`. The finished website is in **`out/`**. For example,
`/about/` maps to `out/about/index.html`. `.next/` contains intermediate build
output and is not the deployment package for this hosting setup.

Upload the **contents** of `out/`, including `_next/`, images, video, and the `.txt`
files used for Next.js navigation. The resulting path must be
`public_html/index.html`, not `public_html/out/index.html`. Do not upload the
repository, `.env*` files, private SSH keys, or `node_modules`.

```bash
pnpm deploy:package
```

This command rebuilds the website and creates **`.deploy/tsets-cpanel-static.zip`**
using the system `zip` utility. `index.html` is at the archive root. The archive
is recreated each time so that files removed since the previous build do not
remain in it. The command does not upload anything. Git ignores `.deploy/` and
`out/`.

## Recommended manual deployment without GitHub integration

Use **FTPS** for the current handover. For frequent future updates, `rsync` over
SSH would make transferring changes easier once shell access is enabled.
Neither method requires connecting the GitHub repository to the hosting account.

1. Back up the current `public_html` locally or use cPanel Backup.
2. Run `pnpm lint`, `pnpm typecheck`, and `pnpm build`.
3. Upload the **contents of `out/` to `/`** using FTPS. Transfer `_next/`, images,
   video, and other supporting assets first, then HTML and navigation `.txt`
   files. Keep old hashed `_next/` assets during deployment because open pages
   may still use them. Overwriting files via FTPS is not an atomic replacement
   of the whole website; deploy during a period of low traffic.
4. Preserve `.htaccess`, `.well-known/`, `.user.ini`, `php.ini`, and `cgi-bin/`.
   Do not automatically delete everything that is absent from `out/`. Removed
   pages remain on the server with this approach; delete obsolete routes
   individually after making a backup and verifying the new version.
5. Verify the homepage, direct navigation and refresh on subpages, team profiles,
   articles, images, video, languages, `mailto:`, and a nonexistent URL returning 404.
6. To roll back, restore the backed-up files and remove specific newly added
   routes if necessary. The local ZIP is a copy of the version being deployed,
   not a backup of the server.

Alternatively, run `pnpm deploy:package`, upload the ZIP using cPanel File Manager,
and extract its contents into `public_html`. Move the archive outside the public
document root after use. The existing `.htaccess` already contains the correct
directives:

```apache
DirectoryIndex index.html
ErrorDocument 404 /404.html
```

Also preserve the PHP configuration block generated by cPanel. This export does
not require rewriting every URL to `index.html`.

## Handover notes

- The contact form requires a working email client; it does not deliver via SMTP.
- `/template-controls/` is an exported public page for template settings.
- The project has no separate language URLs, sitemap, or robots.txt.
- The October 24, 2026 inspection verified the build: 26 HTML files, 191 files in
  total, approximately 27.56 MiB. Local file references in the exported HTML resolved.
